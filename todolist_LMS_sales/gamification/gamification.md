## 0. 한 문장 컨셉

사용자가 직접 만든 할 일을 **작은 퀘스트로 쪼개** 하나씩 클리어하고, 완료한 순간마다 **눈에 보이는 성취**(칭호·성장 게이지·성취 로그)가 쌓이는 할 일 관리 서비스.

---

## 1. 이번 개정의 3가지 목표

### ① 더 쉽게 — 시작 장벽을 낮춘다
- 첫 보상 문턱을 **할 일 1개 완료**로 둔다(즉시 성취감).
- 기본 난이도는 가볍게, "작게 시작해도 충분합니다" 톤 유지.
- 미완료는 **실패가 아니라 `대기 중`·`다시 도전`·`쪼개기 필요`**로 표현(벌점·스트릭 페널티 없음).

### ② 더 작은 단위로 — 큰 일을 잘게 쪼갠다 (이번 개정의 핵심)
- 모든 할 일에 **"쪼개기"** 기능 → **서브 퀘스트(체크리스트)** 생성.
- **부분 완료도 보상**: 서브 퀘스트 1개 클리어마다 소량 XP + 진행률 상승.
- **마이크로 퀘스트(≤10분)**를 1급 단위로 — "한 걸음" 단위의 잦은 완료.
- 큰 할 일은 자동으로 `쪼개기 필요`로 안내해 작은 실행으로 유도.

### ③ 더 잘 보이게 — 성취를 다층으로 시각화한다
- 퀘스트 카드 **상태 색 변화**(대기 → 진행 → 클리어).
- **4단계 성장 게이지**: 오늘 / 이번 주 / 프로젝트 / 전체.
- **성취 로그**: 완료한 일이 사라지지 않고 타임라인으로 쌓임.
- 마인드맵 **노드 점등** + 프로젝트 진행률 바.
- **주간 리포트**로 한 주의 완료를 한눈에.

---

## 2. 용어 매핑

| 할 일 관리 | 게임화 | 의미 |
|---|---|---|
| 할 일 | 퀘스트 | 사용자가 직접 입력한 실행 항목 |
| 하위 할 일 | **서브 퀘스트** | 큰 할 일을 작게 나눈 단계(체크리스트) |
| 체크 완료 | 클리어 | 끝냈다는 상태 |
| 프로젝트 | 퀘스트 보드 | 여러 퀘스트가 묶인 공간 |
| 미룬 할 일 | 대기 퀘스트 | 아직 클리어 안 함 |
| 오래 미룬 할 일 | 쪼개기 필요 | 더 작게 나누면 좋은 항목 |
| 완료 기록 | 성취 로그 | 완료가 쌓이는 기록장 |
| 완료 패턴 | 칭호 조건 | 행동에 따라 칭호를 주는 기준 |

---

## 3. 퀘스트를 "더 작게" — 쪼개기 / 서브 퀘스트 / 마이크로 퀘스트

### 3-1. 쪼개기(Split)
큰 할 일은 `쪼개기 필요`로 표시하고 **쪼개기 버튼**을 제공한다.

큰 할 일 판단 기준:
- 하루 안에 끝내기 어렵다 / 완료 기준이 모호하다 / 여러 단계가 섞여 있다 / 오래 미뤘다.

예:
- "사업 준비하기"(너무 큼) → 쪼개기 → "아이템 후보 3개 적기", "경쟁사 3곳 보기", "한 줄 소개 쓰기"

### 3-2. 서브 퀘스트(체크리스트) — 부분 완료도 보상
- 한 퀘스트 안에 작은 단계를 둘 수 있다.
- 서브 1개 클리어 = **+2 XP** + 퀘스트 진행률 상승(예: 3개 중 1개 = 33%).
- 모든 서브 클리어 시 퀘스트 자동 클리어 + 본 보상 지급.
- 효과: **큰 일을 하는 도중에도 계속 눈에 보이는 진전**이 생긴다.

### 3-3. 마이크로 퀘스트(≤10분)
- 예상 시간 10분 이하 = "한 걸음" 퀘스트로 표시.
- 마이크로 10개 완료 시 칭호 **"한 걸음의 달인"**.
- 가장 쉬운 시작점으로 권장(시작 장벽 최소화).

---

## 4. 퀘스트 상태 (실패 상태 없음)

| 상태 | 의미 | 표현 |
|---|---|---|
| 대기 중 | 아직 시작 안 함 | 차분한 흐린 카드 |
| 진행 중 | 하는 중 | 강조 색 + 빛나는 테두리 |
| 거의 완료 | 서브 일부 완료/마감 임박 | 클리어 직전 |
| 클리어 | 완료 | 밝은 색 + 체크/별 |
| 기록됨 | 성취 로그 저장됨 | 성취 기록 |
| 다시 도전 | 멈췄다가 재시작 | 재도전 가능 |
| 쪼개기 필요 | 너무 큼/오래 미룸 | "더 작게 나누기" 버튼 |

---

## 5. 난이도 & XP (작은 보상을 자주)

| 단위 | XP |
|---|---:|
| 서브 퀘스트 1개 | +2 |
| 쉬움(≤10분, 마이크로) | +5 |
| 보통(기본) | +10 |
| 어려움 | +20 |
| 미루던 일 | +25 |
| 프로젝트 마지막 할 일(마무리) | +30 |

- 난이도는 **사용자가 선택**하거나 기본값 사용(새 할 일=보통, ≤10분=쉬움, 오래 미룸=미루던 일, 프로젝트 마지막=마무리).
- 원칙: **XP는 보조 장치**. 숫자보다 완료 기록·시각화를 우선.

### 레벨 / 칭호(레벨)
누적 XP 기준. 다음 레벨까지 남은 XP를 항상 게이지로 표시.

| 레벨 | 누적 XP | 레벨 칭호 | 아이콘 |
|---|---:|---|---|
| Lv1 | 0 | 새싹 | 🌱 |
| Lv2 | 40 | 일꾼 | 🔨 |
| Lv3 | 100 | 능력자 | ⚡ |
| Lv4 | 200 | 마스터 | 🎯 |
| Lv5 | 350 | 전설 | 👑 |
| Lv6 | 550 | 그랜드마스터 | 🏆 |

> 문턱을 v1(50/120/250…)보다 **낮춰** 더 빨리·자주 레벨업이 보이도록 조정.

---

## 6. 칭호 시스템 (행동 패턴 기반, 10종)

분야가 아니라 **완료 방식**으로 준다. 담백한 톤.

| 칭호 | 조건 | 강화 감정 |
|---|---|---|
| 첫 클리어 | 첫 할 일 완료 | 시작했다 |
| 오늘의 해결사 | 하루 3개 이상 완료 | 오늘 해냈다 |
| 꾸준한 실행자 | 7일 중 5일 완료 | 지속하고 있다 |
| 난관 돌파 | '어려움' 할 일 완료 | 어려운 걸 넘었다 |
| 재시작한 사람 | 미룬 일 다시 시작해 완료 | 다시 해도 된다 |
| 마무리 장인 | 프로젝트 마지막 할 일 완료 | 끝까지 했다 |
| 작은 승리 수집가 | 쉬움 10개 완료 | 작은 완료의 누적 |
| 한 걸음의 달인 | ≤10분 마이크로 10개 완료 | 시작 장벽을 낮췄다 |
| 밀린 일 정리자 | 오래된 할 일 3개 완료 | 정리·회복 |
| 쪼개기의 달인 | 큰 일을 쪼개서 끝까지 완료 | 작게 나눈 성공 |

표시: 완료 순간 팝업 · 프로필 칭호 슬롯 · 칭호 컬렉션 · 주간 리포트의 "이번 주 획득 칭호".

---

## 7. 성취 시각화 (가시화)

### 7-1. 성장 게이지 (4단계)
- **오늘** 완료 수 / **이번 주** 완료 수 / **프로젝트** 진행률 / **전체** 레벨 게이지.
- 작은 단위 완료가 즉시 여러 게이지에 반영되어 "방금 한 일이 보인다".

### 7-2. 성취 로그(타임라인)
완료한 퀘스트가 사라지지 않고 쌓인다. 기록 항목: 할 일 이름 · 완료 시각 · 난이도 · XP · 획득 칭호 · 프로젝트.
목적: **"내가 한 일이 사라지지 않는다"**.

### 7-3. 마인드맵 노드 점등
- 완료 노드 = 밝게 켜짐 / 미완료 = 중립 / 오래 미룸 = 흐린 회색 + "쪼개기" 버튼(경고색 아님).

### 7-4. 주간 리포트
완료 퀘스트 수 · 가장 많이 완료한 요일 · 가장 진행한 프로젝트 · 획득 칭호 · 다시 시작하면 좋은 대기 퀘스트.

---

## 8. 완료 피드백 문구 (담백한 톤, 발췌)
- "퀘스트 클리어!"
- "작은 완료가 오늘의 흐름을 만들었어요."
- "방금 완료한 일이 프로젝트 진행률을 올렸어요."
- "미루던 일을 하나 끝냈어요. 꽤 큰 전진입니다."
- "오늘의 보드가 조금 더 밝아졌습니다."

재도전 문구:
- "멈춘 일은 실패가 아니라 대기 중인 일입니다."
- "10분짜리 작은 퀘스트로 바꿔볼까요?"

## 9. 데이터 구조 (개정 반영)

### todos (확장)
| 필드 | 설명 |
|---|---|
| id / project_id / category_id | 기존 |
| title | 사용자 입력 원문(변경하지 않음) |
| completed | 클리어 여부 |
| **status** | pending / active / cleared / retry / split_needed |
| **difficulty** | easy / normal / hard / delayed / finishing |
| **estimated_minutes** | 예상 시간(마이크로 판단) |
| **xp_reward** | 완료 시 XP |
| **cleared_at** | 완료 시각(주간 리포트·연속 실행용) |

### subtasks (신규 — 서브 퀘스트)
| 필드 | 설명 |
|---|---|
| id / todo_id | 소속 퀘스트 |
| title | 서브 단계 |
| done | 완료 여부 |
| position | 순서 |

### achievement_logs (신규 — 성취 로그)
| 필드 | 설명 |
|---|---|
| id / user_id / todo_id / project_id | 식별 |
| xp | 획득 XP |
| title_awarded | 획득 칭호 |
| message | 완료 문구 |
| created_at | 기록 시각 |

### titles / user_titles (신규 — 칭호 보관)
- titles: id, name, condition_type, condition_value, description
- user_titles: id, user_id, title_id, awarded_at

> 모든 신규 테이블은 기존처럼 **owner 기반 RLS**로 본인 데이터만 접근.

## 10. Mindash 적용 로드맵 (작은 단위 → 가시화 순)

**현재 v1(적용됨):** 완료 수 기반 XP(10/개)·레벨·누적 업적·컨페티·토스트.

**이번 개정 반영 단계:**
1. **레벨 문턱 하향**(40/100/200/350/550) — 더 자주 레벨업이 보이게. *(코드만 수정, DB 불필요)*
2. **서브 퀘스트(체크리스트)** — `subtasks` 테이블 + 카드에 체크리스트, 부분 완료 +2XP·진행률. *(작은 단위의 핵심)*
3. **난이도 + 난이도별 XP** — `difficulty`·`xp_reward` 컬럼, 카드에 난이도 뱃지·보상 미리보기.
4. **성장 게이지 4단계** + **마이크로(≤10분)** 표시.
5. **성취 로그** — `cleared_at` + `achievement_logs`, 완료 타임라인 화면.
6. **칭호 10종** + 칭호 컬렉션 페이지(`titles`/`user_titles`).
7. **주간 리포트** — `cleared_at` 집계.

> 1번은 즉시, 2~3번이 "더 작게/더 쉽게"의 핵심, 4~7번이 "더 잘 보이게"의 확장.

## 11. 피해야 할 설계
1. 사용자가 입력한 할 일 이름을 과장된 게임식으로 바꾸기
2. 특정 분야에만 맞는 퀘스트 타입
3. 포인트 획득이 완료보다 중요해지는 구조
4. 매일 접속 안 하면 스트릭이 깨져 실망시키는 구조
5. 미완료를 실패·패배·벌점으로 표현
6. 알림으로 완료 압박
7. 비교·감시로 느껴지는 랭킹
8. 칭호를 유치하거나 과장되게 표현
