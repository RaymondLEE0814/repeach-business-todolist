# 할 일 관리 서비스 게이미피케이션 설계

## 핵심 정의

이 서비스는 사용자가 스스로 할 일을 정하는 할 일 관리 프로그램이다. 서비스가 사용자의 목표나 분야를 제한하지 않는다. 사용자는 공부, 업무, 운동, 창작, 정리, 영업, 개발, 자기계발, 생활 루틴 등 어떤 일이든 직접 입력할 수 있다.

게이미피케이션의 목적은 사용자가 직접 정한 할 일을 게임처럼 바꾸어, 완료했을 때 "내가 해냈다"는 감각을 더 강하게 느끼게 만드는 것이다.

핵심은 할 일을 대신 정해주는 것이 아니라, 사용자가 정한 할 일을 다음처럼 경험하게 만드는 것이다.

- 할 일 = 퀘스트
- 완료 = 클리어
- 반복 완료 = 성장
- 어려운 일 완료 = 칭호 획득
- 완료 기록 = 성취 로그
- 누적 완료 = 시각적 성장

---

## 한 문장 컨셉

사용자가 직접 만든 할 일을 퀘스트처럼 클리어하고, 완료한 순간마다 칭호와 시각적 성취 기록이 쌓이는 할 일 관리 서비스.

---

## 게이미피케이션 원칙

1. 사용자가 입력한 할 일의 의미를 바꾸지 않는다.
2. 특정 분야나 직업, 연령, 과목에 묶지 않는다.
3. 보상은 사용자를 조종하기보다 완료한 일을 더 잘 느끼게 해야 한다.
4. 실패를 강조하지 않고, 다시 시작할 수 있는 상태로 표현한다.
5. 포인트보다 "완료 장면", "칭호", "기록", "시각적 변화"를 우선한다.
6. 사용자가 매일 접속하지 않았다고 손해 보는 구조를 만들지 않는다.
7. 게임적 표현은 재미있게 쓰되, 할 일의 진지함을 가볍게 만들지 않는다.

## 기본 용어 매핑

| 일반 할 일 관리 용어 | 게임화 용어 | 서비스 안의 의미 |
|---|---|---|
| 할 일 | 퀘스트 | 사용자가 직접 입력한 실행 항목 |
| 체크 완료 | 클리어 | 사용자가 해당 할 일을 끝냈다는 상태 |
| 프로젝트 | 퀘스트 보드 | 여러 할 일이 묶인 공간 |
| 하위 할 일 | 서브 퀘스트 | 큰 할 일을 작게 나눈 항목 |
| 미룬 할 일 | 대기 퀘스트 | 아직 클리어하지 않은 항목 |
| 오래 미룬 할 일 | 잠긴 퀘스트 | 다시 시작하거나 쪼개야 하는 항목 |
| 완료 기록 | 성취 로그 | 완료한 퀘스트가 쌓이는 기록 |
| 반복 완료 | 연속 클리어 | 특정 기간 동안 꾸준히 실행한 기록 |
| 완료 패턴 | 칭호 조건 | 사용자의 행동에 따라 칭호를 주는 기준 |

## 사용자 경험 흐름

### 1. 사용자가 할 일을 정한다

사용자는 평소처럼 할 일을 직접 입력한다.

예시:
- 제안서 초안 쓰기
- 운동 30분 하기
- 책상 정리하기
- 영어 단어 20개 외우기
- 고객 3명에게 연락하기
- 블로그 글 발행하기

이 단계에서 서비스는 할 일을 추천하거나 강요하지 않는다. 사용자의 입력을 그대로 존중한다.

### 2. 할 일이 퀘스트 카드로 바뀐다

할 일을 만들면 서비스는 그것을 퀘스트 카드처럼 보여준다.

퀘스트 카드에 표시할 정보:
- 퀘스트 이름
- 상태
- 난이도
- 예상 시간
- 보상 미리보기
- 완료 시 기록될 성취 문구

예시:

```text
퀘스트: 제안서 초안 쓰기
상태: 대기 중
난이도: 보통
예상 시간: 45분
완료 보상: 집중력 +10
클리어 기록: 오늘의 실행 한 걸음
```

난이도와 예상 시간은 사용자가 직접 정하거나, 서비스가 선택지만 제공한다.

난이도 예시:
- 쉬움
- 보통
- 어려움
- 오래 걸림
- 미루던 일

### 3. 사용자가 퀘스트를 시작한다

사용자가 할 일을 시작하면 상태가 `진행 중`으로 바뀐다.

상태 변화:

```text
대기 중 -> 진행 중 -> 클리어 -> 성취 로그에 기록
```

필요하면 다음 상태도 사용할 수 있다.

```text
대기 중 -> 진행 중 -> 잠시 멈춤 -> 다시 도전 -> 클리어
```

시작 시 문구:
- "퀘스트를 시작했어요."
- "이제 이 일을 클리어할 차례예요."
- "작게 시작해도 충분합니다."

### 4. 사용자가 할 일을 완료한다

사용자가 체크 버튼을 누르면 단순 완료가 아니라 클리어 연출이 나온다.

완료 순간 구성:
- 퀘스트 카드가 밝아짐
- 체크 아이콘이 클리어 아이콘으로 바뀜
- 짧은 완료 문구 표시
- 경험치 또는 성장 게이지 증가
- 조건을 만족하면 칭호 획득
- 완료 기록이 성취 로그에 저장

완료 문구 예시:
- "퀘스트 클리어!"
- "오늘 하나를 끝까지 해냈어요."
- "완료 기록이 성취 로그에 저장됐습니다."
- "작은 완료가 오늘의 흐름을 만들었어요."
- "미루던 일을 하나 끝냈어요. 이건 꽤 큰 전진입니다."

### 5. 완료한 일이 시각적으로 남는다

완료한 할 일은 사라지지 않는다. 사용자는 자신이 해낸 일을 볼 수 있어야 한다.

시각화 방식:
- 완료 카드가 성취 로그에 쌓임
- 완료한 노드가 빛나는 색으로 바뀜
- 프로젝트 보드의 진행 게이지가 채워짐
- 칭호 컬렉션에 새 항목이 열림
- 오늘 완료한 퀘스트가 하루 기록으로 남음
- 주간 리포트에서 완료한 퀘스트 수와 유형을 보여줌

---

## 퀘스트 상태 설계

| 상태 | 의미 | 사용자에게 보여줄 표현 |
|---|---|---|
| 대기 중 | 아직 시작하지 않은 할 일 | 아직 열리지 않은 퀘스트 |
| 진행 중 | 현재 하고 있는 할 일 | 진행 중인 퀘스트 |
| 거의 완료 | 일부 진행했거나 마감이 가까운 할 일 | 클리어 직전 |
| 클리어 | 완료한 할 일 | 퀘스트 클리어 |
| 기록됨 | 완료 후 성취 로그에 저장된 상태 | 성취 기록 저장 |
| 다시 도전 | 미뤘거나 중단했다가 다시 시작하는 상태 | 재도전 가능 |
| 쪼개기 필요 | 너무 크거나 오래 미뤄진 할 일 | 더 작은 퀘스트로 나누기 |

실패 상태는 만들지 않는다. 사용자가 완료하지 못한 일은 실패가 아니라 `대기 중`, `다시 도전`, `쪼개기 필요`로 표현한다.

---

## 칭호 시스템

칭호는 특정 분야가 아니라 행동 패턴에 따라 준다. 사용자가 어떤 일을 하든, 완료 방식에 따라 칭호를 받을 수 있어야 한다.

| 칭호 | 획득 조건 | 강화하는 감정 |
|---|---|---|
| 첫 클리어 | 첫 번째 할 일을 완료 | 시작했다는 감각 |
| 오늘의 해결사 | 하루에 3개 이상 완료 | 오늘 해냈다는 만족감 |
| 꾸준한 실행자 | 7일 중 5일 이상 완료 | 지속하고 있다는 감각 |
| 난관 돌파 | 어려움으로 표시한 일을 완료 | 어려운 일을 넘었다는 감각 |
| 재시작한 사람 | 미뤄둔 일을 다시 시작 후 완료 | 다시 해도 된다는 감각 |
| 마무리 장인 | 프로젝트의 마지막 할 일을 완료 | 끝까지 해냈다는 감각 |
| 작은 승리 수집가 | 쉬운 할 일 10개 완료 | 작은 완료의 누적감 |
| 집중 모드 클리어 | 타이머를 켜고 할 일 완료 | 몰입했다는 감각 |
| 밀린 일 정리자 | 오래된 할 일 3개 완료 | 정리와 회복감 |
| 한 걸음의 달인 | 10분 이하 할 일 10개 완료 | 시작 장벽을 낮춘 성취감 |

칭호 표시 방식:
- 완료 순간 팝업
- 프로필 칭호 슬롯
- 칭호 컬렉션 페이지
- 주간 리포트에 "이번 주 획득 칭호" 표시

칭호 문구는 너무 과장하지 않는다. 사용자가 부끄럽지 않게 느낄 정도의 담백한 톤을 유지한다.

## 보상 시스템

### 1. 경험치

경험치는 완료의 크기를 숫자로 보여주는 보조 장치다.

추천 규칙:
- 쉬움: 5 XP
- 보통: 10 XP
- 어려움: 20 XP
- 미루던 일: 25 XP
- 프로젝트 마지막 할 일: 30 XP

주의할 점:
- 경험치가 목적이 되면 안 된다.
- 숫자보다 완료한 일의 기록과 시각화를 더 강조한다.

### 2. 성장 게이지

사용자의 누적 완료를 보여준다.

게이지 종류:
- 오늘의 성장
- 이번 주 성장
- 프로젝트 성장
- 전체 성취 성장

### 3. 배지

배지는 특별한 패턴을 달성했을 때 준다.

배지 예시:
- 첫 퀘스트 클리어
- 10개 클리어
- 50개 클리어
- 미뤄둔 일 클리어
- 프로젝트 하나 완료
- 일주일 동안 5일 실행

### 4. 성취 로그

성취 로그는 완료한 퀘스트가 쌓이는 기록장이다.

기록 항목:
- 완료한 할 일 이름
- 완료 날짜
- 난이도
- 받은 경험치
- 획득 칭호
- 속한 프로젝트

성취 로그의 목적은 "내가 한 일이 사라지지 않는다"는 느낌을 주는 것이다.

### 5. 꾸미기 보상

후순위 기능으로 프로필이나 보드 꾸미기 요소를 제공할 수 있다.

예시:
- 퀘스트 카드 테마
- 완료 이펙트 색상
- 프로필 프레임
- 칭호 배경
- 프로젝트 보드 스킨

## 성취 시각화 설계

### 퀘스트 카드

대기 중:
- 흐린 색
- 얇은 테두리
- 잠긴 느낌 없이 차분한 상태

진행 중:
- 강조 색상
- 진행 표시
- 작은 움직임 또는 빛나는 테두리

클리어:
- 밝은 색
- 체크 또는 별 아이콘
- 완료 시간 표시
- 성취 로그로 이동하는 버튼

### 프로젝트 보드

프로젝트가 있는 경우, 각 할 일은 보드의 노드로 표현할 수 있다.

시각화:
- 완료한 노드는 밝게 켜짐
- 완료하지 않은 노드는 중립 색상
- 오래 미룬 노드는 빨간 경고 대신 흐린 회색과 "쪼개기" 버튼
- 프로젝트 진행률은 전체 노드 중 클리어 비율로 계산

### 성취 로그

완료한 퀘스트가 시간순으로 쌓인다.

표현 방식:
- 오늘 클리어
- 이번 주 클리어
- 프로젝트별 클리어
- 칭호 획득 기록
- 어려운 일 클리어 기록

### 주간 리포트

일주일에 한 번 사용자의 완료 기록을 보여준다.

포함 내용:
- 완료한 퀘스트 수
- 가장 많이 완료한 요일
- 가장 많이 진행한 프로젝트
- 획득한 칭호
- 다시 시작하면 좋은 대기 퀘스트

문구 예시:
- "이번 주에는 12개의 퀘스트를 클리어했어요."
- "가장 많이 움직인 프로젝트는 '개인 포트폴리오'였어요."
- "미뤄둔 퀘스트 2개를 다시 시작하면 다음 주 흐름이 더 좋아집니다."

## 할 일 생성 시 게임화 규칙

사용자가 할 일을 입력하면 다음 절차로 퀘스트화한다.

### 1. 원문 유지

사용자가 입력한 할 일 이름은 그대로 유지한다.

예:
- 입력: "방 청소하기"
- 퀘스트 이름: "방 청소하기"

서비스가 마음대로 "청소 던전 정복"처럼 바꾸지 않는다. 게임화 표현은 카드, 상태, 보상, 완료 연출에 붙인다.

### 2. 크기 판단

할 일이 너무 크면 `쪼개기 필요`로 표시한다.

큰 할 일의 기준:
- 하루 안에 완료하기 어렵다.
- 완료 기준이 모호하다.
- 여러 단계가 섞여 있다.
- 사용자가 오래 미뤘다.

예:
- "사업 준비하기" -> 너무 큼
- "사업 아이템 후보 3개 적기" -> 좋음

### 3. 난이도 선택

사용자가 직접 난이도를 선택하거나 기본값을 쓴다.

기본값:
- 새 할 일: 보통
- 10분 이하: 쉬움
- 오래 미룬 할 일: 미루던 일
- 프로젝트 마지막 할 일: 마무리

### 4. 보상 미리보기

퀘스트 카드에 완료 시 받을 보상을 미리 보여준다.

예:
- "완료하면 10 XP와 '오늘의 실행' 기록을 얻습니다."
- "미뤄둔 일을 끝내면 '재시작한 사람' 칭호 조건이 채워집니다."

### 5. 완료 후 기록

완료하면 다음 데이터를 저장한다.

- 할 일 이름
- 완료 시간
- 난이도
- 프로젝트
- 경험치
- 획득 칭호
- 완료 당시 문구

## MVP 구현 우선순위

### 1. 퀘스트 카드

사용자가 만든 할 일을 퀘스트 카드처럼 보여준다.

필수 요소:
- 퀘스트 이름
- 상태
- 난이도
- 완료 버튼
- 보상 미리보기

### 2. 클리어 연출

완료 버튼을 누르면 짧은 클리어 피드백을 보여준다.

필수 요소:
- "퀘스트 클리어" 문구
- 카드 색상 변화
- 경험치 증가
- 성취 로그 저장

### 3. 칭호 시스템

처음에는 5개 칭호만 적용한다.

MVP 칭호:
- 첫 클리어
- 오늘의 해결사
- 꾸준한 실행자
- 난관 돌파
- 재시작한 사람

### 4. 성취 로그

완료한 할 일을 모아서 볼 수 있는 화면을 만든다.

필수 요소:
- 날짜별 완료 기록
- 퀘스트 이름
- 획득 경험치
- 획득 칭호

### 5. 프로젝트 진행 시각화

프로젝트가 있는 경우 완료한 할 일의 비율을 보여준다.

필수 요소:
- 전체 할 일 수
- 완료한 할 일 수
- 진행률
- 완료한 카드 강조

## 피해야 할 설계

1. 사용자가 입력한 할 일을 과하게 게임식 이름으로 바꾸기
2. 특정 분야에만 맞는 퀘스트 타입 만들기
3. 포인트를 많이 얻는 것이 할 일을 끝내는 것보다 중요해지는 구조
4. 매일 접속하지 않으면 스트릭이 깨져 실망하게 만드는 구조
5. 미완료 할 일을 실패, 패배, 벌점으로 표현하기
6. 알림을 너무 많이 보내 완료 압박을 주기
7. 팀이나 친구 기능에서 비교와 감시로 느껴지는 랭킹 만들기
8. 칭호를 너무 유치하거나 과장되게 표현하기

## 바로 사용할 에이전트 프롬프트

```text
너는 범용 할 일 관리 서비스의 게이미피케이션 기획 에이전트다.

이 서비스는 사용자가 스스로 할 일을 정하고 완료하는 프로그램이다. 서비스는 공부, 업무, 운동, 창작, 정리, 영업, 개발 등 특정 분야로 사용자를 제한하지 않는다. 사용자가 직접 입력한 할 일을 퀘스트처럼 보여주고, 완료했을 때 게임처럼 성취감을 느끼도록 칭호, 완료 연출, 성취 로그, 시각적 기록을 설계하는 것이 목표다.

중요한 원칙:
1. 사용자가 입력한 할 일 이름과 의미를 마음대로 바꾸지 마라.
2. 특정 분야나 연령, 직업에 맞춘 설계로 제한하지 마라.
3. 할 일을 추천하는 것보다, 사용자가 정한 할 일을 완료했을 때 성취감을 느끼게 하는 데 집중하라.
4. 완료는 "클리어"로 표현하되, 실패나 미완료는 벌점으로 표현하지 마라.
5. 포인트보다 칭호, 완료 기록, 시각적 변화, 성장 로그를 우선하라.

다음 항목을 설계하라.

1. 사용자가 할 일을 입력했을 때 퀘스트 카드로 바뀌는 과정
2. 할 일의 상태값: 대기 중, 진행 중, 클리어, 다시 도전, 쪼개기 필요
3. 완료 순간의 시각적 연출
4. 완료 시 보여줄 문구 20개
5. 칭호 시스템 10개
6. 경험치와 성장 게이지 규칙
7. 성취 로그 화면 구성
8. 프로젝트가 있는 경우 진행률 시각화 방식
9. MVP에서 먼저 만들 기능 5개
10. 피해야 할 게이미피케이션 설계

문체는 한국어로 작성하라. 너무 유치하거나 과장된 게임 표현을 피하고, 사용자가 "내가 해냈다"는 감각을 자연스럽게 느끼도록 차분하지만 기분 좋은 톤으로 설계하라.
```
